# 朗读中转

**让你手机上任何"能改 API 地址"的 AI 对话客户端，自动把 AI 的回复念出来。**

跑在安卓上的本地 API 中继，自带语音引擎系统：不改客户端、不要 root、不用 Xposed。

---

## 为什么会有这东西

市面上大把 OpenAI 兼容的对话客户端**根本没有朗读功能**——不是"不支持某种 TTS"，是整块都不存在。装个包扒一下就知道：没有 `android.speech.tts`，没有 TTS 权限，前端 bundle 里连"语音""朗读"两个字都搜不到。

但这类客户端**绝大多数都能自定义 API 地址**。所以换个思路：

> **别去改它的界面，去它的 API 那一层动手。**

```
你的客户端 ──API主机──► 127.0.0.1:8788 (本 App) ──► 你的模型服务
                             │
                             │ 边转发边扒 SSE 流里的 delta.content
                             ▼
                    断句 ─► 语音引擎 ─► MediaPlayer 🔊
```

请求和响应**逐字节原样透传**，你的 API Key 只在 header 里路过，本 App 不解析、不保存、不打印。

## 语音引擎：三种

以前必须外挂 TTS Server；现在发声这件事自己也能干，三选一（可以并存，按音色挂不同引擎）：

| 类型 | 是什么 | 适合 |
|---|---|---|
| **手机系统语音** | 调系统 TTS（任何装了中文语音包的手机都有） | 零配置、离线、够用 |
| **HTTP 引擎** | 一个返回音频的地址，含 **TTS Server** 的转发器 | 已经有 TTS Server / 自己的服务 |
| **JS 插件引擎** | 兼容 TTS Server 的插件协议（`PluginJS.getAudio` / `EditorJS.*`），Rhino 直接跑插件脚本 | 想要具体某个声音、某条官方链路 |

[TTS Server](https://github.com/jing332/tts-server-android) 仍然完全支持：把它当一路 HTTP 引擎挂上就行，插件也直接导入。

## 能挂哪些客户端

**凡是能自定义 API 地址的 OpenAI 兼容客户端都能用**：

| 客户端 | |
|---|---|
| Chatbox（安卓 / 桌面） | ✅ |
| SillyTavern 酒馆 | ✅ 走 `Custom (OpenAI-compatible)` |
| NextChat / ChatGPT-Next-Web | ✅ |
| LobeChat | ✅ |
| Open WebUI | ✅ |
| Cherry Studio | ✅ |
| 其它自建的 OpenAI 兼容前端 | ✅ |
| 官方 ChatGPT / DeepSeek / Grok App | ❌ 不让改 API 地址 |

判断标准就一条：**设置里能不能把 API 主机改成自定义地址**。能，就能挂。

## 用法

**1.** 装本 App（[ Releases 下载 APK ](../../releases)）

**2.** 打开 App →「引擎」页里选一个发声引擎（系统语音最省事），点 **「启动中转」**

**3.** 打开你用的客户端，把 **API 主机 / Base URL** 改成：

```
http://127.0.0.1:8788/v1
```

**API 路径 `/chat/completions` 不用动。** 改完发消息，AI 就开始念了。

> 想改回去就填回原来的地址。

## 界面

五个标签：**首页 / 朗读 / 设置 / 引擎 / 日志**。

- 整套是 Material 3；Android 12+ 跟随壁纸取色（Material You），深色/浅色/跟随系统都能手选
- 首页大卡一眼看运行状态，暂停 / 静音 / 下一句就在手边
- 「朗读」页：音色、试听、语速 / 音调 / 音量、分角色朗读、断句方案
- 「引擎」页：引擎列表、参数、导入导出、插件界面
- 点音色行的「编辑」进**单音色编辑页**：这个音色自己的语速 / 音量 / 音高，以及插件自己的界面（比如语气指令）

## 它做对了哪些细节

- **断句五档** —— 自然句 / 短句快出声 / 长句少切 / 按行条目 / 整段，点一下就换、即时生效（见下）
- **分角色朗读** —— 按角色名给不同音色：GAL 标记、`名字：` 前缀、酒馆主提示词推断说话人，单角色聊天也能对上
- **同一说话人连续几句合并合成** —— 不再一句一停，语气连贯，请求也少
- **音色级配置** —— 语速 / 音量 / 音高、插件自己的数据（语气之类）都按音色分别存，换音色不会串
- **边下边播** —— 插件吐一块就放一块，不等整句下完
- **下游掉线不慌** —— 连不上就熔断退避（2s→30s）不再猛敲；**失败的那句留着不丢**，下游回来自动补念
- **原样透传** —— 流式、非流式、`/v1/models` 全部照转，客户端的"打字机"效果不受影响
- **流水线** —— 合成第 N+1 句时第 N 句正在播，**句与句之间零空档**
- **一句是一句** —— 上一句没播完，下一句绝不插队
- **懒打断** —— 只有真的要念新正文时才打断旧朗读；"会话标题生成"这类不发声的请求**不会**把正在念的回复清空
- **联网搜索 / 工具调用照念** —— agent 循环里"搜索结果回灌后"的那一发正是最终答复，既不会因为工具结果里带个 `"title"` 字段被误判成后台小活，也不会把**前一段没念完的正文腰斩**
- **新问题才打断** —— 判定看"末条消息"：末条是 `user` = 新的一轮，打断；末条是 `tool` = 同一回合的后半截，排队
- **播放看门狗** —— 音频焦点被抢导致静默暂停、或播放循环意外停摆，都会自动救回
- **自动跳过代码块** —— ` ``` ` 围栏内的内容不念（连跨 chunk 的半个围栏都认）
- **Markdown 清洗** —— 链接、图片、井号、列表符号、emoji 全刮掉再念
- **跳过思考过程** —— `reasoning_content` 不念，只念正文
- **导入导出** —— 自己的 JSON（含插件脚本，能原样恢复）、阅读(Legado) 的朗读引擎 JSON
- **CORS 全开** —— 网页版客户端直连也能用，预检 `OPTIONS` 已处理
- **不需要 root** —— 就是一个普通的前台服务

## 断句方案（五种）

同一段回复，切法不同，听起来完全是两回事。「朗读」页里点一下就能换，**改完立刻生效、不用重启**。

| 方案 | 在哪儿断 | 适合 | 代价 |
|---|---|---|---|
| **自然句**（默认） | 句末标点（`。！？；…`）与换行 | 通用，最像人念书 | —— |
| **短句 · 快出声** | 逗号、顿号、冒号**也算断点**，且第一块特意切短 | 嫌它半天不出声；第一块只有几个字，张嘴就来 | 碎，语气被切得断断续续 |
| **长句 · 少切几次** | 先把短句**攒**到 ~70% 上限再发 | 请求少、语气连贯、不容易被拖死 | 第一声要等（要攒够才合成） |
| **按行 / 条目** | **只在换行处**断 | 列表、步骤、剧本、歌词 —— 一行一句 | 一整行太长时才会退让硬切 |
| **整段 · 超长才切** | 几乎不主动断，只在超过「单句最长字数」时切一刀 | 要最连贯的整段朗读 | 单块最大 = 第一声最慢，也最容易卡 |

五者之外的公共规则：

- 硬切时**不会从句子中间劈**：在上限前一半的窗口里找**优先级最高**的标点（句末 > 分号 > 逗号 > 冒号 > 空格），找不到才真硬切。
- 洗完只剩符号的块直接丢（`……`、`***`、纯 emoji、纯代码块都不会进 TTS）。
- 短句不再被长度门槛吞掉：`好。` 这种 2 字回复以前会被扔掉，现在照念。

想先看看切出来什么鬼样子，不用真让它念：

```bash
curl "http://127.0.0.1:8788/_split?mode=1"              # 0~4
curl "http://127.0.0.1:8788/_split?mode=1&chunk=40"     # 顺便试不同上限
curl "http://127.0.0.1:8788/_split?text=随便一段话&mode=3"
```

返回切好的数组。它跟真实链路一样按 **3 字一段**喂进去，所以增量逻辑也一并验了。

## 本地调试接口

中继在 `127.0.0.1:8788` 上开了一组 `/_` 开头的接口，出问题一查就知道：

| 接口 | 作用 |
|---|---|
| `GET /_status` | 运行状态、已念句数、失败次数、卡死救回次数 |
| `GET /_log` | **完整日志**（落盘，重启不丢）—— 排障主要看这个 |
| `GET /_selftest` | 自检：不连模型，直接跑一遍断句→跳代码块→合成→播放（并把切法写进日志） |
| `GET /_split?text=&mode=&chunk=` | **干跑断句**：返回切好的数组，看方案差别、不用真出声 |
| `GET /_engines` / `/_engine?id=&k=&v=` | 引擎列表 / 切当前引擎、改某个配置项 |
| `GET /_voices` / `/_voice?v=名字` | 列音色（多引擎合并）/ 换音色 |
| `GET /_ttsdata?voice=&k=&v=` | 看（或改）某个音色自己的插件数据 |
| `GET /_export` / `POST /_import` | 导出 / 导入全部引擎配置（自己的 JSON 或 Legado） |
| `GET /_say?text=...` | 立刻念一句 |
| `POST /_check` | **只判定"念不念"、不转发** —— body 塞一段请求 JSON，返回 `speak` 和 `why` |
| `GET /_lastreq` / `/_bindings` | 最近一发客户端请求原文 / 当前解析模式与角色→音色表 |
| `GET /_revive[?force=1]` | 试着拉起外部 TTS |
| `GET /_stop` / `/_mute` / `/_unmute` | 打断 / 闭嘴 / 恢复 |

日志里每一发请求都会记一笔，标明念不念、以及**不念的理由**：

```
[02:12:43] ← POST /v1/chat/completions msgs=4 末条=user(158字) max_tokens=-1 stream=true  →  念
[02:12:49] ← POST /v1/chat/completions msgs=6 末条=tool(2989字) max_tokens=-1 stream=true  →  念（工具轮：搜索结果已回灌，这条是正文）
[02:12:49] ↳ 本轮念出 12 句
[02:13:02] ← POST /v1/chat/completions msgs=1 末条=user(9字)   max_tokens=50   stream=false →  跳过（max_tokens=50，后台小活）
```

## 哪些请求会被念、哪些不念、要不要打断

客户端一次对话常常发好几发请求（正文 + 起标题 + 摘要 + 工具轮…），全念会精神分裂。判定只有三条规矩：

| 情况 | 判定 | 理由 |
|---|---|---|
| `max_tokens` / `max_completion_tokens` < 200 | **不念** | 客户端在后台起标题、写摘要 |
| **末条**是 `role:"tool"`，或末条是带 `tool_calls` 的 assistant | **念，且接在后面不打断** | 联网搜索 / 函数调用回灌后的这一发，是**同一个回合的后半截** |
| `system` / `developer` 提示词里有「标题 / title / 摘要 / summar / 命名」 | **不念** | 起标题的活儿 |
| 其它（末条是 `user` 的新一轮） | **念，并打断上一段** | 你问了新问题，旧的自然让路 |

> 💡 判断"打断不打断"看的是**末条消息**，不是"历史上有没有出现过 tool"。
> 上一轮用过联网搜索、这一轮你问了全新问题 —— 末条是 `user`，照样打断。

> ⚠️ 关键词**只扫 system 提示词**，绝不扫整包 `messages`。
> 踩过的坑：搜索结果里带 `"title"` 字段，老版本扫整包必然命中 → 正牌回复被整段静音。
> 同理，跟 AI 聊 HTML 的 `<title>`、聊标题党，也不会再把整段回复连坐。

## 自己编译（全程在手机上，不用电脑）

需要 Termux + `pkg install aapt2 apksigner d8 openjdk-17 kotlin`，另外准备一份 `android.jar`（见下）。

```bash
git clone https://github.com/mermergi/tts-relay.git
cd tts-relay
./tools/fetch-deps.sh       # 拉依赖 jar/aar（git 里只存 SOURCES.md）
./tools/build.sh            # 编出 out/ttsrelay.apk
./tools/build.sh --install  # 编完直接 adb 装
```

`android.jar` 有 26MB，**没有进仓库**。编译脚本会自己找，找不到就设环境变量：

```bash
export ANDROID_JAR=/path/to/android.jar   # 从任意 Android SDK 的 platforms/android-34/android.jar 拷一份
```

## 已知限制

1. **必须保持本 App 运行**。它是前台服务，划掉任务卡片也不会死，但**被强行停止**（系统设置里点"强行停止"）就会断——这时候客户端会报连接错误，重新打开即可。
2. **声音取决于引擎**。系统语音最省事但音色有限；HTTP / 插件引擎要看对方服务是否稳，插件登录过期、额度用完这类问题会写进「日志」页。
3. **中转不鉴权**。默认只监听 `127.0.0.1`。App 里有个「允许局域网访问」开关，开了绑 `0.0.0.0`，**局域网里谁连上都能用你的 API Key** —— 家里 WiFi 无所谓，公共网络别开。
4. **客户端必须支持自定义 API 地址**，且用 OpenAI 兼容协议（`/chat/completions`）。用 Anthropic / Gemini 原生协议的挂不上。
