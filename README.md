# 朗读中转

**让你手机上任何「能改 API 地址」的 AI 对话客户端，自动把 AI 的回复念出来。**

跑在安卓上的本地 API 中继：不改客户端、不要 root、不用 Xposed。
**自带嗓子**——不装别的东西，开箱就能念。

---

## 为什么会有这东西

市面上大把 OpenAI 兼容的对话客户端**根本没有朗读功能**——不是"不支持某种 TTS"，是整块都不存在。装个包扒一下就知道：没有 `android.speech.tts`，没有 TTS 权限，前端 bundle 里连"语音""朗读"两个字都搜不到。

但这类客户端**绝大多数都能自定义 API 地址**。所以换个思路：

> **别去改它的界面，去它的 API 那一层动手。**

```
你的客户端 ──API主机──► 127.0.0.1:8788 (本 App) ──► 你的模型服务
                             │
                             │ 边转发边扒 SSE 流里的 delta.content
                             ▼
                    断句 ─► 引擎 ─► MediaPlayer 🔊
```

请求和响应**逐字节原样透传**，你的 API Key 只在 header 里路过，本 App 不解析、不保存、不打印。

---

## 嗓子从哪来

本 App **自己带一套引擎系统**，装完默认就走手机自带的系统语音，一句话不用配：

| 引擎类型 | 是什么 | 什么时候用 |
|---|---|---|
| **系统语音** | 直接调安卓原生 TTS（`android.speech.tts`） | 默认。离线、零配置、不联网 |
| **HTTP 接口** | 一个可配的请求模板，指向任意合成服务 | 想换音色/换云服务时 |

[TTS Server](https://github.com/jing332/tts-server-android) 不是必须的，它只是「HTTP 接口」引擎的一个现成例子（音色多、能接一堆云服务）。想用就把它当 HTTP 引擎填进来。

---

## 用法

**1.** 装本 App，打开 → **「启动中转」**

**2.** 打开你用的客户端，把 **API 主机 / Base URL** 改成：

```
http://127.0.0.1:8788/v1
```

**API 路径 `/chat/completions` 不用动。**

**3.** 想换嗓子就去 **「引擎」** 页挑一个。改完即时生效。

> 想改回去就填回原来的地址。

## 能挂哪些客户端

**凡是能自定义 API 地址的 OpenAI 兼容客户端都能用**：

| 客户端 | |
|---|---|
| Chatbox（安卓 / 桌面） | ✅ |
| SillyTavern 酒馆 | ✅ 走 `Custom (OpenAI-compatible)` |
| NextChat / ChatGPT-Next-Web | ✅ |
| LobeChat | ✅ |
| Open WebUI | ✅ |
| Cherry Studio | ✅ |
| 其它自建的 OpenAI 兼容前端 | ✅ |
| 官方 ChatGPT / DeepSeek / Grok App | ❌ 不让改 API 地址 |

判断标准就一条：**设置里能不能把 API 主机改成自定义地址**。能，就能挂。

## 引擎：就是一张键值表

设计上照 [TTS Server](https://github.com/jing332/tts-server-android) 那套思路 —— **引擎是个通用容器，不是一堆写死的类型**：

- 配置是**任意键值表**。下面是"约定键"，知道就自动填好；不知道也拦不住你自己加一个（编辑框里点 **「＋ 加一个键」**）。
- **音色目录由引擎自己声明怎么取**，不是每种引擎写一段拉取代码。
- 想加个自己的参数？加就是了，键名随便起。

### HTTP 接口引擎

指向任意能返回音频字节的服务，地址和参数都是模板：

| 键 | 说明 |
|---|---|
| `url` | 接口地址模板 |
| `method` | `GET` / `POST` |
| `headers` | 请求头，每行一个 `Key: Value` |
| `body` | POST 正文模板 |
| `json_key` | 音频藏在 JSON 的哪个字段（留空 = 响应本身就是音频） |
| `timeout` | 超时毫秒 |
| `login_url` / `binding` / `ua` | 要登录才给数据的接口用，见下面「登录状态」 |

模板里能用的占位符：

```
{{text}}    {{voice}}    {{rate}}    {{pitch}}    {{volume}}
```

例：TTS Server 那两条接口，填进去就是这样 ——

```
url:  http://127.0.0.1:1221/api/tts?text={{text}}&engine=<引擎包名>&rate={{rate}}&pitch={{pitch}}&voice={{voice}}
音色目录地址: http://127.0.0.1:1221/api/voices?engine=<引擎包名>
```

### 音色目录：三路合并

音色不写死在一个地方，而是**三个来源并起来**，谁有算谁的：

| 来源 | 怎么给 |
|---|---|
| 手工填的 | `voices`，一行一个 |
| 从接口拉的 | `voices_url` + `voices_path` / `voices_name` / `voices_id` |
| 引擎自带的 | 系统语音会把它这台机器上装了哪些语音报出来 |

`voices_path` 支持 `data.list` 这种写法（留空 = 响应本身就是个数组）。
显示名和取值分开取，列表里就写成 `名字‖取值`（取值留空 = 同名）。

音色名还能顺手带上标签，拿 `|` 隔开 —— 例如 `小美 女|青年|温柔`，
App 会拆出性别/年龄/风格，**选音色时按男声/女声/未标注分组**，找不到的直接在搜索框里打名字。

### 登录状态

有些接口要先登录才给音色和音频。填上 **`login_url`**（登录页地址），编辑框里就会多一个 **「💾 一键保存」**：

1. 点它 → 内置浏览器打开那个登录页
2. 正常登录
3. 点右上角 **「💾 保存」** —— 值自动填回引擎配置

`binding` 决定保存哪一项：

| 写法 | 取什么 |
|---|---|
| `session` | 该地址下存着的整串 |
| `session.名字` | 只要名字是「名字」的那一条 |
| `local.键` | `localStorage` 里那个键 |
| `store.键` | `sessionStorage` 里那个键 |

不想走登录页也行：点 **「手动填」** 直接粘。**粘什么进去都认** —— 整段复制出来的请求、一段请求头、或者裸的 `名字=值; 名字=值`；带标记的会自动把值摘出来，摘不出就原样收着，绝不截断。保存下来的值会跟着请求一起发出去（手工填的请求头优先）。

### 导入 / 导出

两种格式，别人发的能收，自己导的能还原：

| 格式 | 用途 |
|---|---|
| **本 App 格式**（JSON） | 换手机原样恢复，连 id 一起认，重复导入是覆盖不是叠加 |
| **阅读（Legado）的朗读引擎 JSON** | 圈里互相分享用的就是它，TTS Server 也认 |

支持直接开文件导入、也能复制粘贴。同名同类型的引擎再导一次不会多出一份。

## 多语音朗读

一段回复里既有旁白又有好几个角色的台词 —— 全用一个嗓子念会很出戏。所以带了一套**多语音规则**，规则照着**酒馆（SillyTavern）的 TTS 插件生态**来，不是自己瞎编的启发式：

| 模式 | 念什么 |
|---|---|
| **听书 · 全文都念** | 旁白和台词都用同一个嗓子，最省事 |
| **GAL · 角色标签** | 认 `[角色名][情感][场景]「台词」` 这类标签，按角色分嗓子 |
| **RP · 只念引号** | 只念引号里的台词，旁白略过 |

角色名从几种常见写法里认：`[名字][…]「…」`、`名字: 「…」`、`名字：「…」`，
还有内心/独白（`心里想`、`（内心：…）`）单独一路。
每行写 `角色名 = 音色` 就绑定了，`旁白` 是保留名字，管那些没标角色的正文。

## 它做对了哪些细节

- **五档断句方案** —— 自然句 / 短句快出声 / 长句少切 / 按行条目 / 整段，点一下就换、即时生效（见下）
- **下游掉线不慌** —— 连不上就熔断退避（2s→30s）不再猛敲；**失败的那句留着不丢**，下游回来自动补念；并尽力自动拉起下游服务
- **原样透传** —— 流式、非流式、`/v1/models` 全部照转，客户端的"打字机"效果不受影响
- **流水线** —— 合成第 N+1 句时第 N 句正在播，**句与句之间零空档**
- **一句是一句** —— 上一句没播完，下一句绝不插队
- **懒打断** —— 只有真的要念新正文时才打断旧朗读；"会话标题生成"这类不发声的请求**不会**把正在念的回复清空
- **联网搜索 / 工具调用照念** —— agent 循环里"搜索结果回灌后"的那一发正是最终答复，既不会因为工具结果里带个 `"title"` 字段被误判成后台小活，也不会把**前一段没念完的正文腰斩**（同一回合的续写排队接在后面）
- **新问题才打断** —— 判定看"末条消息"：末条是 `user` = 新的一轮，打断；末条是 `tool` = 同一回合的后半截，排队
- **播放看门狗** —— 音频焦点被抢导致静默暂停、或播放循环意外停摆，都会自动救回
- **自动跳过代码块** —— ` ``` ` 围栏内的内容不念（连跨 chunk 的半个围栏都认）
- **Markdown 清洗** —— 链接、图片、井号、列表符号、emoji 全刮掉再念
- **跳过思考过程** —— `reasoning_content` 不念，只念正文
- **开机自启**（可选）—— 上次是运行状态的话，开机自己拉起来
- **CORS 全开** —— 网页版客户端直连也能用，预检 `OPTIONS` 已处理
- **不需要 root** —— 就是一个普通的前台服务

## 断句方案（五种）

同一段回复，切法不同，听起来完全是两回事。App 的「设置」卡里点一下「断句方案」就能换，**改完立刻生效、不用重启**。

| 方案 | 在哪儿断 | 适合 | 代价 |
|---|---|---|---|
| **自然句**（默认） | 句末标点（`。！？；…`）与换行 | 通用，最像人念书 | —— |
| **短句 · 快出声** | 逗号、顿号、冒号**也算断点**，且第一块特意切短 | 嫌它半天不出声；第一块只有几个字，张嘴就来 | 碎，语气被切得断断续续 |
| **长句 · 少切几次** | 先把短句**攒**到 ~70% 上限再发 | 请求少、语气连贯、不容易被下游拖死 | 第一声要等（要攒够才合成） |
| **按行 / 条目** | **只在换行处**断 | 列表、步骤、剧本、歌词 —— 一行一句 | 一整行太长时才会退让硬切 |
| **整段 · 超长才切** | 几乎不主动断，只在超过「单句最长字数」时切一刀 | 要最连贯的整段朗读 | 单块最大 = 第一声最慢，也最容易卡 |

公共规则：

- 硬切时**不会从句子中间劈**：在上限前一半的窗口里找**优先级最高**的标点（句末 > 分号 > 逗号 > 冒号 > 空格），找不到才真硬切。
- 洗完只剩符号的块直接丢（`……`、`***`、纯 emoji、纯代码块都不会进 TTS）。
- 短句不再被长度门槛吞掉：`好。` 这种 2 字回复以前会被扔掉，现在照念。

想先看看切出来什么鬼样子，不用真让它念：

```bash
curl "http://127.0.0.1:8788/_split?mode=1"              # 0~4
curl "http://127.0.0.1:8788/_split?mode=1&chunk=40"     # 顺便试不同上限
curl "http://127.0.0.1:8788/_split?text=随便一段话&mode=3"
```

返回切好的数组。它跟真实链路一样按 **3 字一段**喂进去，所以增量逻辑也一并验了。

## 本地调试接口

中继在 `127.0.0.1:8788` 上开了一组 `/_` 开头的接口，出问题一查就知道：

| 接口 | 作用 |
|---|---|
| `GET /_status` | 运行状态、已念句数、失败次数、卡死救回次数 |
| `GET /_log` | **完整日志**（落盘，重启不丢）—— 排障主要看这个 |
| `GET /_selftest` | 自检：不连模型，直接跑一遍断句→跳代码块→合成→播放（并把切法写进日志） |
| `GET /_split?text=&mode=&chunk=` | **干跑断句**：返回切好的数组，看方案差别、不用真出声 |
| `GET /_engines` | 列出所有引擎，`?id=` 直接切过去 |
| `GET /_engine?id=&k=&v=&del=` | 改当前引擎的某个配置项 / 删引擎 |
| `GET /_voices[?id=]` | 列音色（`&grouped=1` 按男女分组） |
| `GET /_voice?v=名字` | 换音色 |
| `GET /_say?text=...&roles=1` | 立刻念一句（带角色规则） |
| `GET /_mv` | 看/切多语音模式与角色→音色表 |
| `GET /_import` / `/_export[?fmt=legado]` | 导入 / 导出引擎 |
| `POST /_check` | **只判定"念不念"、不转发** —— body 塞一段请求 JSON，返回 `speak` 和 `why`，用来复现"该念的被静音 / 不该念的被念" |
| `GET /_revive[?force=1]` | 试着拉起下游服务（`force=1` 绕过 60 秒节流） |
| `GET /_stop` | 打断当前朗读 |
| `GET /_mute` / `/_unmute` | 闭嘴 / 恢复 |

日志里每一发请求都会记一笔，标明念不念、以及**不念的理由**：

```
[02:12:43] ← POST /v1/chat/completions msgs=4 末条=user(158字) max_tokens=-1 stream=true  →  念
[02:12:49] ← POST /v1/chat/completions msgs=6 末条=tool(2989字) max_tokens=-1 stream=true  →  念（工具轮：搜索结果已回灌，这条是正文）
[02:12:49] ↳ 本轮念出 12 句
[02:13:02] ← POST /v1/chat/completions msgs=1 末条=user(9字)   max_tokens=50   stream=false →  跳过（max_tokens=50，后台小活）
```

## 哪些请求会被念、哪些不念、要不要打断

客户端一次对话常常发好几发请求（正文 + 起标题 + 摘要 + 工具轮…），全念会精神分裂。判定只有三条规矩：

| 情况 | 判定 | 理由 |
|---|---|---|
| `max_tokens` / `max_completion_tokens` < 200 | **不念** | 客户端在后台起标题、写摘要 |
| **末条**是 `role:"tool"`，或末条是带 `tool_calls` 的 assistant | **念，且接在后面不打断** | 联网搜索 / 函数调用回灌后的这一发，是**同一个回合的后半截** |
| `system` / `developer` 提示词里有「标题 / title / 摘要 / summar / 命名」 | **不念** | 起标题的活儿 |
| 其它（末条是 `user` 的新一轮） | **念，并打断上一段** | 你问了新问题，旧的自然让路 |

> 💡 判断"打断不打断"看的是**末条消息**，不是"历史上有没有出现过 tool"。
> 上一轮用过联网搜索、这一轮你问了全新问题 —— 末条是 `user`，照样打断。
> 反过来，搜索结果刚回灌的那一发末条是 `tool`，就乖乖排队，绝不腰斩正在念的句子。

> ⚠️ 关键词**只扫 system 提示词**，绝不扫整包 `messages`。
> 踩过的坑：联网搜索的结果长这样 —— `{"result":{"searchResults":[{"title":…,"link":…,"snippet":…}]}}`。
> 老版本扫整包，`"title"` 必然命中 → **搜索结果之后那条正牌回复被整段静音**，
> 表现就是"聊到一半一联网，后面就哑了"。同理，跟 AI 聊 HTML 的 `<title>`、聊标题党，也不会再把整段回复连坐。

## 自己编译（全程在手机上，不用电脑）

需要 Termux + `pkg install aapt2 apksigner d8 openjdk-17`，另外准备一份 `android.jar`（见下）。

```bash
git clone https://github.com/mermergi/tts-relay.git
cd tts-relay
./tools/build.sh            # 编出 out/ttsrelay.apk
./tools/build.sh --install  # 编完直接 adb 装
```

`android.jar` 有 26MB，**没有进仓库**。编译脚本会自己找，找不到就设环境变量：

```bash
export ANDROID_JAR=/path/to/android.jar   # 从任意 Android SDK 的 platforms/android-34/android.jar 拷一份
```

签名用的是**自签名调试密钥**（`keystore.jks`，不进仓库，脚本第一次跑会自动生成）。
要发正式包请换成自己的密钥。

## 已知限制

1. **必须保持本 App 运行**。它是前台服务，划掉任务卡片也不会死，但**被强行停止**（系统设置里点"强行停止"）就会断——这时候客户端会报连接错误，重新打开即可。
2. **系统语音引擎因机而异**。安卓各家 ROM 自带的那一套差别很大（有的还要另外装语音包、有的中文只有一两个嗓子）；想统一音色就用 HTTP 接口引擎。
3. **中转不鉴权**。所以默认只监听 `127.0.0.1`。App 里有个「允许局域网访问」开关，开了绑 `0.0.0.0`，**局域网里谁连上都能用你的 API Key** —— 家里 WiFi 无所谓，公共网络别开。
4. **客户端必须支持自定义 API 地址**，且用 OpenAI 兼容协议（`/chat/completions`）。用 Anthropic / Gemini 原生协议的挂不上。
